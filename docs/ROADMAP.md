# Delivery and evidence checklist

Plan against nine hours/week: seven building, one targeted reading, one portfolio/applications.
At eight hours/week, allow about fourteen weeks. Preserve review quality if golden-set
work takes longer; start an exact-cache pilot before the complete benchmark if its gates pass.

| Week | Outcome and evidence |
|---|---|
| 1 | Portable roles, offline endpoint, tiny Worker binding check, full developer/reviewer/QA cycle |
| 2 | Policies, 20 genuinely reviewed answers, 100 human-reviewed questions, baseline |
| 3 | Exact cache, scope isolation, TTL and immutable policy activation |
| 4 | Cosine search, embedding provenance and local shadow demonstration |
| 5 | More reviewed families; development-only threshold analysis |
| 6 | Cloud adapters, repair workflow, CI and 600 public reviewed cases |
| 7 | Access, durable spend and failure/concurrency checks on hosted infrastructure |
| 8 | Five-tester exact-cache pilot; semantic shadow only |
| 9 | Owner-held private review; fresh model and prefix-cache evaluation |
| 10 | Declared traffic cost/latency comparison and hosted recovery/load evidence |
| 11 | Freeze release assessment; decide whether semantic evidence is sufficient |
| 12 | Portfolio case study, short demo video, honest report and operational review |

The implementation automates engineering mechanics across several weeks; it does not compress
human label review or real operational evidence into a fabricated completion claim.

Every task also follows [Mobile QA](MOBILE_QA.md), including backend impact or justified N/A.
UI work needs responsive WebKit regression before merge; implementing that browser gate
remains follow-up work. Generic layouts do not establish actual iPhone Duo Safari support.

## Before the first invited pilot

- [ ] Luis reviews fictional policies and the first 20 reusable answers.
- [ ] Luis reviews 100 golden cases and their family split; ambiguous labels are quarantined.
- [ ] Cloudflare staging account/resources, Access and runtime memberships are configured.
- [ ] Fresh hosted binding, authorization, policy, budget and recovery checks pass.
- [ ] A bounded live model-quality assessment is recorded separately from offline fixtures.
- [ ] GitHub protections/environments and exact-source deployment are exercised.
- [ ] Current reviewer, technical QA and CI evidence passes; rollback is exercised.
- [ ] Mobile layout, touch, keyboard, enlargement and request-state scenarios are verified.
- [ ] Before claiming Duo support, record actual Safari folded/unfolded, both orientations
      and transition evidence, including hardware coverage and any remaining limitations.

## Before semantic serving / portfolio release

- [ ] Complete and human-review 600 public cases with deliberate hard negatives.
- [ ] A separate owner prepares/reviews 400 private cases outside coding environments.
- [ ] Human-approved seed manifest includes source, timestamps, expiry and live embedding provenance.
- [ ] Threshold chosen on development data is frozen before regression/release assessment.
- [ ] Report accepted semantic hits/errors, coverage, uncertainty, cold/warm cost and latency.
- [ ] Maintain shadow mode unless evidence is sufficient; document any failure honestly.
- [ ] Publish only sanitized original files and aggregate reports; inspect Git history.
- [ ] Record fresh Codex cloud setup and agent discovery from a new task.

Portfolio narrative: define the incorrect-reuse risk, show a failing boundary case, explain
the fix and gates, compare against the strong template baseline, and show what the evidence
cannot establish. Avoid claiming production readiness from synthetic tests alone.
